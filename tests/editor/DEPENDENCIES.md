## Selective-loading failure

A local esbuild probe of the built FESM files on 13 November 2026 showed that importing only `CaseNotifier` from `case/editor-source` produces approximately 2,385,102 minified bytes (674,617 gzip bytes) and retains external imports of both payment and Media Viewer. Importing `CaseEditorModule` produces effectively the same output. In contrast, the independent session-storage entry produced 750 bytes (345 gzip bytes) and neither dependency. External dependencies were not bundled, so these numbers are a diagnostic comparison, not a consumer download-size measurement.

Before the notifier split, `node tests/editor/selective-loading.mjs` failed because its non-editor notifier import pulled the editor's heavy dependencies. At that stage, the entry point exported the service alongside the editor module and dialogs, whose transitive Angular metadata kept the shared graph reachable. Split a coherent, independently buildable notifier/service entry point from the editor module, preserve the service's injection identity across consumers, and prove the packed consumer bundle excludes payment and Media Viewer before treating this candidate as ready. This must be addressed before merging: a successful strict package build does not meet the selective-loading design by itself.

A temporary secondary-entry experiment re-exported the existing notifier source without moving it. The strict ng-packagr build failed while compiling that entry (`Cannot destructure property 'pos' of 'file.referencedFiles[index]' as it is undefined`). The experiment was removed. A direct re-export is therefore not yet evidence of a safe split: the notifier imports `CasesService`, which in turn reaches other editor services and models. Moving or re-exporting only the notifier risks duplicate Angular class identities; a real split must give each shared class a single owning entry point and verify injection identity from the packed package.

A second temporary experiment moved the notifier to a single new owning entry point and made the editor re-export that same class, while retaining the existing concrete `CasesService` dependency. Ng-packagr rejected the entry point as circular before compilation. The files were restored. This demonstrates that changing the export alone is insufficient: the dependency cycle through `CasesService` and editor-owned models/services must be broken or moved together, with constructor injection and class identity tested against real consumers.

An isolated single-owner prototype moved the 61-file static graph and compiled the new notifier entry successfully, but the editor entry then failed with Angular NG6001: `DatePipe` had moved out of the compilation while `PaletteUtilsModule` still declared it.
